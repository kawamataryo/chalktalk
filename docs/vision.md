# プロダクトビジョン（ネタ詰め中・随時更新）

## 一番伝えたいこと

一人で勉強するのは孤独。その孤独を解消し、**本当に一緒に頑張ってくれる先生**がiPadの向こうにいるような体験をつくる。チャットボットに話しかけるのではなく、見守り、話しかけ、都度いちばん分かりやすく説明してくれる存在。

## 誰のためか

- 共働き・きょうだい複数の家庭。朝や夕方、勉強に使える時間はあるが、親は仕事や家事で見てあげられない
- 最初のユーザーは小学5年生の長男（公立中高一貫校の受検勉強中、適性検査Ⅰ・Ⅱ）
- 親は後から学習の様子を見られる

## 決まっていること（2026-11-03 時点）

- iOS ネイティブ（SwiftUI）、iPad 中心
- 頭脳は Claude。音声は「端末内の聞き取り → Claude → 読み上げ（ElevenLabs 有力）」の3段構成
- キーボード不要。声が主役、カメラで「見て」と言えば撮影
- 学習セッション中は聞き続け、ウェイクワードは補助
- 答えは言わない。ヒントを段階的に出し、最後は一緒にたどって答えは子どもに言わせる
- 問題の種類（読み取り・思考・作文）ごとに伴走の仕方をプロンプトで切り替える
- 説明は Generative UI（用意した部品＋Claude が描く SVG/HTML）。画像生成は最後の手段
- 先生は実写ではなく 2D または 3D キャラ（長男はマイクラ・アニメ好き）。大学生くらいのお兄さん・お姉さん先生、やさしいくだけた口調
- 先生から話しかける：時間での声かけ（休憩・集中）は必須、様子を見ての声かけにも挑戦
- 前回の内容を覚えていて、始まりと終わりにふり返る。親への共有の材料にもなる
- 長く使い続けて改善していくプロダクトとして作る（入賞より実用）

## 決まっていること（追加分）

- 先生はオリジナルのボクセル風3Dキャラ（マイクラの模倣はしない）。見た目・名前・声はひとまずこちらで決め打ちし、後で長男と調整
- 割り込み（barge-in）対応：長男が話し始めたら先生は止まって聞く。難所なので、うまくいかないときはマイクを止める方式に切り替えられるようにする
- 見守り：端末内の Vision で手の動き・顔の有無だけを見る。ノートは「ちょっと見せて？」と聞いてから撮影
- 雑談：休憩中はOK。勉強中は少し付き合ってから、やさしく勉強に戻す。依存させすぎない安全ルールも入れる
- モデル：会話は `claude-haiku-5-5`、問題の分析・ヒント・図の生成は `claude-sonnet-5-5`。速さが必要な判断（「見て」の意図判定、声かけのタイミング、部品選びなど）は TypeSafe AI の Jev（Decision API）を積極的に使う
- クラウド：Cloudflare Workers＋D1。APIキーを守る中継サーバーも同じ Worker にまとめる。親は Web ダッシュボードで見る
- ログインは Google アカウント。まずは自分の家庭用で作り、複数家庭対応は後回し
- 保存するのは文字の情報だけ（要約・学習記録・つまずき・好きなこと）。写真と音声は処理後に捨てる
- iPad は iOS 26 に上げられる
- 11/8 までに作るもの：①声の対話の土台（割り込み込み）②「見て」で撮影→ヒント→Generative UI ③ボクセル先生アバター ④時間での声かけ＋前回の記憶 ⑤クラウド同期＋親ダッシュボード ⑥Vision での見守り＋Jev。雑談の記憶の磨き込みは後回し

- 読み上げ（TTS）：差し替え可能な作りにし、まず ElevenLabs Flash で実装。最初の実機確認で ElevenLabs / Azure / Gemini / Aivis を長男と聞き比べて決める。定型句は事前生成してキャッシュ、オフライン時は Apple 標準 TTS
- Apple Developer Program 加入済み、Xcode 最新・実機デバッグ経験あり、Cloudflare / Google / TypeSafe AI / Anthropic のアカウントあり。キックオフ済み

## 開発の進め方

- リポジトリ `kawamataryo/chalktalk`（はじめは `ai-home-teacher`。名前を ChalkTalk に決めて改名）を公開、MIT ライセンス
- issue: 作る順番①〜⑥に対応する親 issue と、半日以内で終わる子 issue。子 issue には完了条件と確認方法（自動テスト / シミュレーター / 実機）を書く。`実機確認` ラベル、マイルストーン「11/8 提出」。日本語で書く
- AI はこの Mac で auto mode ＋ `/goal` を使い、issue ごとに worktree → 実装 → テスト → PR → テスト通過で自動マージ。`実機確認` の issue は止めてユーザーのチェックを待つ
- ユーザーは毎日1時間、AI が用意した実機チェックリストを iPad で確認する。初日は最大のリスク（日本語の音声認識、割り込み時のエコー）から確認する
- 秘密情報は `.gitignore` と Cloudflare の secret で管理し、リポジトリには入れない
