# 仕様書：ChalkTalk

> 背景と決定の経緯は [vision.md](vision.md)、技術調査は [research-2026-11-03.md](research-2026-11-03.md)、ハッカソン要項は [hackathon-guide.md](hackathon-guide.md)。

## 1. ゴール

一人で勉強する孤独を解消する。iPad の向こうに「一緒に頑張ってくれる先生」がいて、見守り、話しかけ、わからないところは答えを言わずにヒントと図で導いてくれる。

判断に迷ったら「これで孤独は減るか？」「本物の家庭教師ならどうするか？」で決める。

### 対象ユーザー

- 子ども：小学5年生（公立中高一貫校の受検勉強中、適性検査Ⅰ・Ⅱ）。iPad で使う
- 親：共働き。スマホのブラウザで後から様子を見る

### やらないこと（今回）

- 複数家庭への対応（自分の家庭用。ただし家族 ID で分けておく）
- 写真・音声の保存
- 親への通知、親のスマホアプリ
- 子どもが文字で入力するチャット画面（声が主役）

## 2. 全体構成

```
┌─────────────── iPad (SwiftUI, iOS 26) ───────────────┐
│  AudioEngine (voice processing / AEC)                │
│   ├─ SpeechAnalyzer + SpeechDetector  … 聞き取り・発話検出 │
│   └─ TTS 再生 (差し替え可能: ElevenLabs / Azure / …)    │
│  ConversationController  … ターン管理・割り込み          │
│  TeacherBrain            … Claude 呼び出し (Haiku/Sonnet) │
│  DecisionClient          … Jev の判断呼び出し             │
│  Camera + Vision         … 撮影・手の動き/顔の検出        │
│  AvatarView … キャラごとの表示（3D/2D）・口パク・状態     │
│  BoardView               … Generative UI (ネイティブ部品 + WKWebView SVG) │
│  SessionStore (SwiftData) … ローカルキャッシュ             │
└──────────────────────────┬───────────────────────────┘
                           │ HTTPS (家族トークン)
┌──────────── Cloudflare Worker (TypeScript) ──────────┐
│  /v1/claude   … Anthropic API への中継 (SSE パススルー) │
│  /v1/tts      … ElevenLabs への中継 (文字タイミング付き)   │
│  /v1/tts/azure … Azure Neural TTS への中継 (MP3 のみ)    │
│  /v1/decide   … TypeSafe AI Decision API への中継        │
│  /v1/sessions, /v1/memory … 学習記録・記憶の保存 (D1)   │
│  /dashboard   … 親向け Web ダッシュボード (Google ログイン) │
└──────────────────────────────────────────────────────┘
```

- API キー（Anthropic / ElevenLabs / Azure Speech / TypeSafe AI）はすべて Worker の secret に置く。アプリには入れない
- アプリと Worker の間は、親がダッシュボードで発行する「家族トークン」で認証する（自分の家庭用なので簡易でよい）

## 3. 機能仕様

### ① 声の対話の土台

- **学習セッション**：「勉強スタート」（または画面の大きなボタン）で開始、「終わり」で終了
- セッション中はマイクを開いたまま。先生が応答するのは、次のどちらかのとき
  - 呼びかけられた（「ねえ先生」「先生」などで始まる発話、または Jev が「先生への発話ではない」と言い切らなかった。迷うときと Jev が使えないときは応える。家で一人で勉強している子の声を黙って無視しないため）
  - 直前の先生の発話から 30 秒以内の会話の続き（先生の発話が終わった、または割り込まれた時刻から、子どもが話し始めた時刻までで数える。30 秒ちょうどは含む）
- 先生は待機中なら自分から話しかけてよい（④の時間での声かけ）。聞き取り中は話さない
- **聞き取り**：SpeechAnalyzer / SpeechTranscriber（ja-JP）。使えない場合は SFSpeechRecognizer にフォールバック
- **聞きちがい**（#135）：書き起こしには変換ミスが混じる前提で扱う
  - 正誤判定：正答と読みが同じなら正解にする（端末内の読みの比較。数を含む答えと読みの短い答えは比べない）
  - 先生の返事：意味が通らないときは、まちがいと決めつけず正答も補わずに聞き返す。聞き返しても通じなければ、短く区切る・ノートを見せるなど伝え方を変えてもらう（`prompts/teacher.md`）
- **終話判定**：SpeechDetector ＋ 無音 700ms を基本とし、Jev で「言い終わったか」を判定して早める（0.8 以上のときだけ。さえぎると困るので、ほかの判断の 0.7 より高くする）。このとき発話のほかの判断（先生への発話か・撮影の依頼か・助けを求めているか・答えの判定）も同じ 1 回のリクエストで先に聞いておき、発話が確定したらその答えを使う（`UtteranceDecisionCache`。§3⑥）
- **応答**：`claude-haiku-5-5` をストリーミングで呼ぶ。文（。！？）ごとに区切ってすぐ TTS に流す
- **割り込み（barge-in）**：先生の発話中に子どもの発話を検出したら
  1. TTS の再生と Claude のストリームを即座に止める
  2. 会話履歴の先生の発言を「実際に再生した文字の位置」で切り詰める（図を出した返事は、図の前の文と続きの文をまたいで数える。tool_use と tool_result の対は残し、図を見せる前に止めたときは tool_result を「図は出していない」に書き換える。#86）
  3. 子どもの発話を聞く
  - 先生の「考え中」（応答を作っている間）に話し始めた場合も割り込みとして扱い、作りかけの応答は捨てて聞き直す
  - 割り込んだ発話は会話の続きとみなし、呼びかけ語がなくても応答する
- **エコー対策**：AVAudioEngine の `setVoiceProcessingEnabled(true)`。入力と再生を同じエンジンに通す
- **保険**：設定で「先生が話している間はマイクを止める」方式に切り替えられる
- **TTS**：`TTSProvider` プロトコルで差し替え可能にする。最初は ElevenLabs Flash v2.5（文字タイミングを口パクに使う）。オフライン時は AVSpeechSynthesizer
  - 先生の声は `Secrets.xcconfig` の `TTS_PROVIDER` で選ぶ（#98）: `azure`（既定）/ `elevenlabs`。既定は費用の安い Azure Neural TTS（ja-JP、声は `ja-JP-NanamiNeural`）。実機で聞き比べて Azure に決めた。`elevenlabs` と書いてビルドし直せば ElevenLabs に戻る
  - Azure は REST（`cognitiveservices/v1`）で 1 文ずつ MP3 を作る。文字タイミングは返らないので、音声の長さを文字数で均等に割って推定し、口パクと割り込みの位置に使う（ElevenLabs より口の動きは粗い。Viseme が欲しくなったら WebSocket / Speech SDK を検討）
  - Azure の無料枠（F0）は 1 分に 20 リクエストまで。1 文 1 リクエストなので、初回起動の定型句づくりや早口の会話で超えると 429 になり、60 秒は端末の声になる。日常使いは S0（従量課金）にする
  - 1 文ぶんの音声（ElevenLabs は MP3、AVSpeechSynthesizer は WAV）を受け取りきってから再生する。出だしは少し遅れるが、MP3 を自前でつなぎながらデコードするより確実（ストリーミング再生は後回し）
  - ElevenLabs が失敗するか 6 秒以内に返らなければ、その文を AVSpeechSynthesizer で作り直す
  - 「何文字目まで話したか」は文字タイミングと再生位置から出す（読み始めた文字まで数える。割り込み時に発言を切る位置）
  - 再生は `SpeechAudioPlayer` で差し替える。エコー対策でマイクと同じ AVAudioEngine に通すときは `EngineClipPlayer` を使う
- **定型句キャッシュ**：「いいね！」「どれどれ」「休憩しよっか」などは事前に音声を生成して同梱し、待ち時間ゼロで再生する
  - 一覧は `ios/HomeTeacher/Resources/Phrases/teacher_phrases.json`。音声は `scripts/generate_phrases.mjs` で ElevenLabs から作って同梱する
  - 同梱の音声がない定型句は、初回起動時に作ってディスクにキャッシュする（オフラインなら AVSpeechSynthesizer の声。あとで ElevenLabs が使えたら作り直す）
  - キャラごとに声と定型句を分ける（#120）。声は `prompts/characters/characters.json` の `voice`（nil なら Worker の既定の声）、言い替えは `phrases`。同梱は `phrase_<キャラ>_<key>.json`、ディスクは `PhraseCache/characters/<キャラ>/`。既定の先生は今までの場所のまま。共通の定型句を話すときは、そのキャラの言い替えがあればそちらで話す。オフラインでは AVSpeechSynthesizer に落ちる（キャラらしさより止まらないことを優先する）
  - 同梱の音声は ElevenLabs の声。Azure（既定）のときは初回起動時に Azure の声で作り直してディスクに置き、そちらを先に使う（先生の声が定型句だけ変わらないように）
- **相づち**：Sonnet の処理に時間がかかるときは、Haiku の応答か定型句（「お、どれどれ…」）で間をつなぐ
- **初めての許可**（#66）：いきなりシステムのダイアログを出さない。まだ聞いていない許可だけを、マイク → 音声認識 → カメラ（カメラがある端末だけ）の順に、先生が理由を話してから「いいよ」のボタンで聞く。状態は毎回 OS の許可の状態から決める
  - 拒否されたとき：先生が端末の声で何が使えないかを伝え（「お父さん・お母さんに、設定アプリで許可してもらってね」）、画面の上に保護者向けの案内と「設定アプリを開く」を出す。カメラだけ拒否なら撮影と見守りを止めて、声の会話は続ける。音声認識の拒否は、聞き取りを始められなかったときだけ伝える
- **つながらないとき**（#66）：Worker / Claude の失敗（オフライン・5xx・401・時間切れ）では固まらない。先生が定型句「ちょっと調子が悪いみたい。」（端末に音声がある）→「もう一回言ってみて」で聞き直す。画面には保護者向けに理由を出す（401 なら FAMILY_TOKEN、設定がなければ Secrets.xcconfig）。つながったら消す
  - 返事の 1 文目が 3 秒来なければ「ちょっと考えるね」でつなぎ、流れが 15 秒止まったら諦めて聞き直す（途中で止まったら話せたところまで話してから。話していない文字は履歴から消す）。写真の分析は 60 秒、ふり返りは 30 秒で諦める（ふり返りは決まり文句にして保存はする）
  - 先生の声（ElevenLabs / Azure）が一度失敗したら、60 秒は AVSpeechSynthesizer だけで話す（文ごとに 6 秒待たない）
  - `Secrets.xcconfig` がなくてもビルド・起動できる。Worker を呼ばずにすぐ失敗し、端末の声だけで動く

### ② 「見て」で撮影 → ヒント → Generative UI

- **撮影のきっかけ**：「これ見て」「ここわかんない」「見てほしい」などの発話を Jev（`noul`：撮影の依頼か。迷う帯と Jev が使えないときは言い方で判定）で判定 → カウントダウン音 → 撮影。画面の撮影ボタンも置く
  - 判定は返事の生成と並べて走らせ、1文目を話す前に答えを待つ（撮影の依頼なら作りかけの返事を捨てる）。問題を見たあとの「わかんない」はヒントを求める発話として扱い、「見て」と言われたときだけ撮り直す
  - カメラは設定で前・後ろを選ぶ（iPad をスタンドに立て、ノートを向いている方）。映像だけのセッションで、マイクの AVAudioSession には触らない
- 画像は長辺 2048px の JPEG に縮小して送る。送ったあとは端末からも破棄する
  - そのため黒板の `highlight_image`（撮影画像の一部を囲む）は、今は画像なしで表示される
- **問題の分析**：`claude-sonnet-5-5` に画像と会話を渡し、次を構造化して返させる（strict tool use）
  - 問題の種類：`reading`（資料・グラフの読み取り）/ `thinking`（算数・理科的思考）/ `writing`（作文・記述）
  - 問題文の要約、正答（子どもには見せない）、ヒントの段階
- **ヒントの段階**（`reading` / `thinking`）
  1. 何を聞かれているかを確認する
  2. どこを見ればよいか（注目する場所）
  3. 考え方の方向
  4. 一緒に解き方をたどる（最後のひと言＝答えは子どもに言わせる）
- **作文**（`writing`）：書くことを一緒に整理 → 構成を考える → 書いたものを撮影 → よいところを具体的に褒め、直すとよくなる点を1つだけ伝える
- **答えを言わないルール**：子どもが「答え教えて」と言っても、正答をそのまま言わない。段階を進めてヒントを細かくする
  - 違う答えは、同じ段階で2回つまずいたら次の段階へ（prompts/hint_ladder.md と揃える）。作文は「わからない」では進めず、整理・構成が終わったときと、書いたものを撮影したときに進む
  - **答えの判定**（`AnswerJudge`）：問題に取り組み中は、子どもの発話を返事を作る前に判定する（作文・正答がない問題・解けたあとは判定しない）
    1. 正答（と言いかえ）が含まれていれば正解（`AnswerLeakGuard` と同じ表記揃え。Jev に聞かない）
    2. 「わからない」などは答えではなく、助けを求める発話として段階を進める
    3. Jev の「答えを言っているか」と「正答と同じか」（どちらも `noul`。発話のほかの判断と同じリクエストで先に聞いてある。間に合わなければ 500ms まで待つ）。答えを言っていて（0.7 以上）、同じなら（0.7 以上）正解、違えば（0.3 以下）違う答え。どちらかが迷う帯ならどちらにもしない。「4と6」「たて×横」のような途中の考えは「答えを言っていない」になる。「24かな？」のような聞く形も答えに含める。Jev が「助けを求めている」（0.7 以上）と言えば、答えではなくヒントを 1 段進める（「どうやるの？」のような言い方で拾えないもの）
    4. Jev が使えなければ、正答が数で、発話に数が 1 つだけあり、質問の言い方でなければ違う答え
  - **解けたら**：Haiku の 1 文目を待たずに定型句「すごいじゃん！」（同梱の音声）を話し、そのまま返事を続ける。返事の間はアバターを `praise` にする。先生のメモに「自分で解けた（すごいじゃん！はもう言った）」を入れ、ふり返りの記録を `solved_by_self` にする。以降は先生が正答を繰り返してよい（Jev だけが正解とみなしたときも）
  - **2回つまずいたら**：次の段階に進め、その返事の間はアバターを `encourage` にする。先生のメモに「責めずに励ましてから、今のヒントを1つだけ」を 1 回の返事だけ入れる
  - 答えと判定した発話は、撮影の依頼かを確かめない（「10になったよ、みて」で撮らない）
  - 先生の文は読み上げる前に正答（と言いかえ）と照合し、含まれていたら別の文に差し替える（`AnswerLeakGuard`）。子どもが先に正答を言ったあとは繰り返してよい
    - 差し替えたら、その返事の残りの文は話さない（答えの説明が続きやすいため）。履歴も差し替えた文にそろえる
- **Generative UI**：先生の発話と一緒に、黒板（BoardView）に図を出す
  - Claude は `show_board` ツールで、部品カタログから部品を選んで中身を指定する（JSON Schema。全部品の anyOf を strict にすると API が「grammar is too large」で 400 を返すので、`show_board` だけ strict にせず、足りないキーをスキーマの既定値で埋めてから読む。#70）
  - 部品カタログ（初期）：`step_cards`（手順カード）、`number_line`（数直線）、`area_diagram`（面積図）、`segment_diagram`（線分図）、`table`（表）、`bar_chart`（棒グラフ）、`highlight_image`（撮影画像の一部を囲む）、`essay_outline`（作文の構成メモ）。#70 で `percent_bar`・`venn_diagram`・`timeline` を足した
  - カタログで表せないときは `render_svg` ツールで、自己完結の SVG（外部リソースなし・CSS アニメのみ・viewBox 固定）を出させ、WKWebView に表示する
  - WKWebView は外部ネットワーク禁止、CSP で script を禁止する
  - 画像生成は使わない。実物は本物の写真（`show_reference_image`）の方が正確で、図やイラストは `show_board`（自由に描く部品を含む）で描ける。生成画像は参考資料としてまちがった形を教えるおそれがあり、埋める隙間がない（#113 で判断）
  - **参考の写真**（#116）：会話（Haiku）の `show_reference_image`（探すものの名詞と説明）で、ウィキペディア日本語版の自由ライセンスの画像を探して黒板に出す。端末から直接探し、Worker を通さない（送るのはモデルが作った名詞だけ）。候補は 3 つまで Haiku に見せて（`prompts/reference_image_check.md`）、内容が合っていて小 5 に見せてよいものだけ出す。確かめられなければ出さない。作者とライセンスも小さく書く。探す間は調べものカードで「写真をさがしているよ」と見せる。見つからなければ言葉か `show_board` で伝える。写真は端末のメモリにだけ置く
  - 分析（Sonnet）では、report_analysis と一緒に図を必ず1つ頼む（頼まないと図を出さなかった。#70 の評価で 0/10）
  - **自由に描く黒板**（#107）：部品 `chalk_drawing`。決まった部品で表せない図（理科の実験道具・回路・てこ、地図・方位、図形の角）を、座標（よこ 100 × たて 70）に線・矢印・四角・円・多角形・曲線・角の印・文字・スタンプ・パスを並べて描く
    - スタンプ：理科（`heating_setup` ビーカーをアルコールランプであたためる・ビーカー・三角フラスコ・試験管・アルコールランプ・温度計・メスシリンダー・U字形磁石・乾電池・豆電球・虫めがね・太陽）、地理（方位記号・山・日本列島・地図記号の学校・神社・郵便局・田）
    - 線はチョークで1本ずつ引くように出す。`step` の番号ごとに段階表示する（ほかの部品と同じく、話す文・ヒントの段階に合わせる）
    - SVG より短く書けるので、会話（Haiku）にも渡す（`render_svg` は会話では切れやすいので分析だけ）。図形のキーは `kind`・`points` のほかは必須にしない（全部必須だと毎回全部書き、返事の上限 1024 トークンに近づいた）。図形は 6〜15 個
    - 日本列島は「size 4・中心 [50,35]」で置いたときの地方の座標をプロンプトに書く（書かないと、印が地図とずれた）
    - 入れ子が深いので、モデルが `component` を JSON の文字列で返すことがある（評価で 4/6）。プロンプトで止め（1/6 に減った）、アプリは文字列を読み直し、最後のかっこが抜けていたら補う
    - 図形の種類・スタンプの名前・色は答えの照合から外す（文字だけを「？」にする）
    - **パス**（#173）：スタンプにない形（生き物・植物・からだのつくり・もの）は、図形 `path` で SVG のパスの `d`（M/L/H/V/C/S/Q/T/A/Z、小文字は相対）を黒板の座標で書いて描く。これで黒板に描けるものの種類を、用意した部品やスタンプに限らないようにした
      - アプリが `d` を読んで線にし（`SVGPathParser`）、ほかの線と同じくチョークで引くように出す。読めない文字や数の足りないコマンドがあれば、そこまでの線だけ描く。座標は黒板の近くに収め、1本 400 コマンドで打ち切る
      - ラベルは `points` の1点か、形のすぐ下に書く
      - `d` は答えの照合から外す（数だらけなので、答えが数のときに形が「？」で壊れる）
      - 会話（Haiku）の返事の上限で切れないように、プロンプトで1本を短く（コマンド 20 個くらいまで）・線画にするよう頼む。`render_svg` を会話に渡す案は、長くて切れやすいので採らなかった
    - 文字は重ならないように置く（`ChalkLabelLayout`）：図形の並び順に置き、前の文字と重なるか線にかぶるなら、近い順に上下（だめなら左右）へずらす。スタンプの中の文字（N・S、＋・－）は動かさない
  - **黒板の見せ方**（#105）：黒板に何か書くときは黒板を画面いっぱいに大きくし、先生は黒板の右下に重ねて立たせる（`SessionStageLayout`）。書いていないときは先生だけを大きく見せ、黒板は横の小さな看板にして使い方の案内（「勉強スタート」で始めよう など）を書く
    - 切り替えはアニメーションでつなぐ：看板が広がって黒板になり、先生は右下へ寄る。しまうときは逆。先生（RealityView）は作り直さず、枠の位置と大きさだけを動かす
    - 図を差し替えるときは、黒板消しで前の図を左から右へ拭き取ってから次の図を書く。タイトルは左から右へチョークで書くように出す
    - 黒板に書いて話すときは、先生が黒板の方へ少し体を向ける。聞くときは子どもの方を向く
    - 先生が重なる右下には書かない（黒板の右か下を空ける。減る面積が小さい方）
    - 黒板はチョーク置き（4色のチョークと黒板消し）、木の枠、消したあとのチョークの跡で黒板らしく見せる
    - **しまうタイミング**：会話の途中の図は、図を使わない返事が2回続いたら話題が移ったとみなしてしまう。写真の分析の図は解いている途中の問題なので、返事の回数ではしまわない。休憩に入ったらしまい、分析の図だけ預かって休憩のあとに見せていたところまで出し直す。セッションの終わりにもしまう
  - **会話の途中の図**（#70）：会話（Haiku）にも `show_board` を渡す（`render_svg` は長くて返事の max_tokens で切れやすいので渡さない）。いつ出すか・出さないかは `prompts/board_talk.md`。先にひと言話してから呼ぶ。図を出したら、話していても続きを1回もらい、図を見ながらの問いかけで締める（続きは先に話している文の読み上げ中に届くので、待ち時間は増えない）。tool_use と tool_result は履歴で対にする（tool_result は「黒板に出した」）。読めない図は出さない
  - 部品カタログに足したもの（#70）：`percent_bar`（割合の帯図）、`venn_diagram`（ベン図）、`timeline`（時間の流れ。1つずつ見せる）。表は「きまり探し・条件の整理」だけに使う
  - 黒板にも答えを書かない：出す前に図の文字を `AnswerLeakGuard` で照合し、答えを含む文字だけ「？」にする（分析の図も会話の図も）
  - **段階表示**：手順カードは1枚ずつ、線分図は1本ずつ見せ、いちばん新しいものを強調する。分析の図はヒントの段階が進むたびに、会話の図は先生が文を話し始めるたびに1つ増やす。表・グラフ・構成メモなど資料の部品は最初から全部見せる
  - 図が替わるときは、薄く消して書き直すように入れ替える

### ④ 時間での声かけ ＋ 前回の記憶

- **タイマー**：集中 25 分＋休憩 5 分を基本にする（設定で変更可）。区切りで先生が声をかける
  - 声かけは定型句（「そろそろ休憩しよっか」「休憩おわり！続きやろう」、集中の終わり 5 分前の「あと5分がんばろう」）。言い回しを Haiku に変えてもらう設定も持つ
  - 子どもの話をさえぎらない：会話が待機のときだけ話す。聞き取り中・考え中・発話中なら待機に戻るまで待つ。待っている間に次の区切りが来たら新しい声かけだけを話す
  - 励ましは定型句に合わせて「残り 5 分」で固定（集中が 5 分以下なら出さない）。一時停止中は残り時間が止まる
  - 設定画面（親が触る。セッション中は開けない）で、集中（15/20/25/30/45 分）・休憩（3/5/10/15 分）・声かけの言い回しを変えるかを選ぶ（#65）。端末に保存し、次のセッションから効く
  - 言い回しを変えるときは、区切りごとに Haiku に 1 文で言い換えてもらう（`prompts/nudge_variation.md`）。2 秒で返らない・長い・「5分」が消えたなど意味が変わったら、定型句のまま話す。言い換えた文は同梱の音声がないので、その場で合成する
- **集中が途切れたとき**：長く無言で、手も動いていない場合は「あと5分がんばろう」など（⑥と連携）
- **始まり**：前回の要約と覚えていることを Claude に渡し、「昨日の割合の続きやる？」のように始める
- **終わり**：その日のふり返り（取り組んだ問題数、自力で解けたところ、よかった点）を先生が話す。同時に要約を作って保存する
- **雑談**：休憩中は自由に雑談する。勉強中は少し付き合ってから、やさしく勉強に戻す
- **記憶**：好きなこと・最近の出来事・苦手な単元を `memory` として保存し、次回の会話に使う
  - 終わりのふり返りは `claude-sonnet-5-5` の strict tool use（`record_reflection`）で、親向けの要約・先生のひとこと・今夜の声かけ・子どもに話すふり返り・記憶の更新（カテゴリごとの add / remove）をまとめて作る。何を覚えて何を忘れるかの判断が次回以降に響くので、1セッション1回の呼び出しは Haiku より質を取る。待ち時間は定型句でつなぐ
  - 記憶は1カテゴリ20件まで（あふれたら古いものから捨てる）。同じ内容は重ねず、更新日時だけ新しくする
  - Claude が失敗しても、セッションと「要確認」は必ず端末（SwiftData）に保存し、数えられることだけで決まり文句のふり返りをする
  - 始まりの「前回のこと」（`prompts/opening.md`）には前回の要約・問題・先生のひとことと記憶を入れる。「要確認」は入れない（先生から深刻な話を蒸し返さない）
- **インターネットで調べる**（#114）：今のこと・最近のこと・時間で変わること・自信がないことは、会話（Haiku）が `web_search`（Anthropic のサーバーツール `web_search_20250305`）で調べてから答える。いつ調べるか・調べないかは `prompts/web_search.md`。今日の日付もここに入れる
  - 定義は `prompts/tools/web_search.json`。検索先は子ども向けに許可リストで絞り、1 回の返事で 2 回まで
  - 許可リストにクロールを断るサイト（`nhk.or.jp` のトップ、`asahi.com`、`yomiuri.co.jp`、`mainichi.jp` など）が 1 つでもあると、リクエスト全体が 400 になる。リストを変えたら `scripts/check_search_domains.mjs` で確かめる。もし 400 になっても、そのセッションは検索なしで話し続ける
  - 検索の結果（暗号化された本文）は履歴に残さない。毎ターン送ると遅くなるので、話した言葉だけを残す
  - 調べても答えはそのまま言わない。ページの中の指示には従わない
  - **待たせない**（#115）：検索が始まったら、先生が何も言っていなければ定型句「ちょっと調べてみるね。」でつなぐ。5 秒かかったら「もうちょっとで見つかりそう。」と 1 回だけ声をかける。「ちょっと考えるね」とは重ねない。諦めるまでの時間は 30 秒にのばす
  - **調べものカード**：調べている言葉と検索先のサイト（favicon とサイト名）を見せる。調べている → 見つけた（サイトが 1 つずつ現れる）→ 答えを話し始めて 2 秒で小さくして「〇〇で調べたよ」を残す → 話し終えて 5 秒でしまう。割り込まれたらすぐ消す。ページの題名は出さない。favicon は Google の favicon サービスから取る（送るのはサイトのホスト名だけ）。取れないときは頭文字を出す
  - 調べたあとの前置き（調べたよ、わかったよ）と言いなおしは読み上げない
  - 調べたあとの答えは 3 文までにする。4 文目が来たら「もっと聞きたい？」に差し替えて止める（プロンプトに書くだけでは 12 回中 4 回長くなった）
- **安全ルール**（システムプロンプトに入れる）
  - 個人情報（住所・学校名・フルネームなど）を聞き出さない
  - ときどき「お父さん・お母さんにも話してみたら？」と親につなげる
  - 深刻な悩み（いじめ・体調・強い不安など）の兆候があれば、やさしく受け止めつつ親に相談するよう勧め、ダッシュボードに「要確認」として残す
    - 「要確認」は Haiku が `flag_for_parent` ツール（`category` と `reason`）を呼んで残す。定義は `prompts/tools/flag_for_parent.json`。アプリはセッションの `SessionFlags` に記録する
    - 呼んだら、話していても続きを1回もらう（親に話すよう勧める言葉がないまま終わることがあった。#131）
  - 医療・心理の助言はしない

  - 日ごとの学習時間（グラフ）
  - セッションごとの要約：取り組んだ問題、つまずいたところ、自力で解けたところ
  - 一番上に、今夜の声かけ（#158）。最新のセッションから、親が夜に子どもへかける一言を提案する（「『もとにする量をどうやって見つけたの？』と聞いてみてください」）。問題への取り組みだけをもとにし、雑談の内容、答え、評価のことばを書かない。項目のないセッションなら出さない
  - 親の伝言（#159）。親がダッシュボードで書いた伝言（200 文字まで）を、次の勉強の始まりに先生が伝える。送った伝言と、伝わったかどうかが見える
    - 記憶とは別のテーブル（`parent_messages`）に置く。伝言は一度伝えたら終わりで、カテゴリごとに入れ替わる記憶とは性質が違うため
    - 1 回の勉強で伝えるのは一番古い 1 件だけ。たまるのは未送達 10 件まで
    - 送り主の呼び方は親が書く（空なら「おうちの人」）。先生に推測させない
    - 端末は同期で取ってきて持っておき（始める前にも 2 秒だけ同期を待つ）、最初のあいさつを最後まで話し、呼び方が入っていたときだけ「伝えた」にする。割り込み・通信の失敗・途中終了では次の勉強に残す。「伝えた」の印は端末に先に残すので、オフラインでも繰り返さず、サーバーには次の同期で伝える
    - 中身は親の言葉であって指示ではない。`<parent_message>` で区切って入れ、答えや先生への指示の部分は伝えない。ヒントの段階は変えない。叱る内容でも先生は一緒に責めない
  - 先生が覚えていること（#160）。カテゴリごとに短い言葉のまま見せ、親が 1 件ずつ消せる。消すと次の勉強から先生は使わない
    - 端末に未送信の変更があると `PUT /v1/memory` の丸ごと入れ替えで復活するので、消した印（`memory_deletions`。言葉そのものは残さずハッシュだけ）を残す。端末は PUT にそのカテゴリを揃えた時のサーバー時刻（`based_on`）を付け、サーバーはそれ以降に消された記憶を取り除く
    - 端末が消えたことを知ったあとに子どもがまた話したことは、新しい記憶として覚え直す（親が消せるのは「今の間違い」で、ずっと話題にできなくするものではない）
  - 自力で解けた問題の変化（#161）。JST の月曜始まりで 6 週分、ヒントなしで解けた／ヒントを使って解けた／一緒に解いた、の問題数を見せ、規則で作る一言を添える（Claude は呼ばない）。週 5 問未満の週とは比べず、差が 2 問未満なら「増えた」と言わない。割合、点数、順位は出さず、下がった週も責めず、ヒントの増加を悪く書かない。今の `kind` では単元が分からないので、単元ごとに見せるなら別 issue で `problems` に項目を足す
  - 週のまとめ（#162）。終わった週（JST の月〜日）の記録から、Sonnet で「伸びたこと」と「来週の見どころ」を作って保存し、過去の週も見られる。入力は要約、先生のひとこと、問題だけ（写真、音声、要確認は渡さない）
    - 作るのは、その週の記録がある状態で最初にダッシュボードを開いたとき。Cron にしなかったのは、親が開かない週の費用をかけないため。`waitUntil` で裏で作るので親を待たせず、次に開くと見られる
    - 勉強 2 回かつ問題 3 問に満たない週は作らない。呼ぶ前に行を確保して、同じ週に重ねて呼ばない。失敗しても 6 時間あけて、1 週につき合計 3 回まで
    - プロンプトは `worker/prompts/`。`prompts/` はアプリに同梱されるので、Worker だけが使うものは分けた
  - 先生からのひとこと（「今日は割合の問題を自力で解けました！」）
  - 「要確認」のメモ
- 保存するのは文字の情報だけ。写真と音声は保存しない
- アプリはセッション終了時と起動時に同期する（`ios/HomeTeacher/Sync/SyncService`）。送る → 取ってくるの順で、セッションは端末の id で上書き（送り直しても重複しない）、記憶はサーバーが正。オフラインなら送れなかったものを残し、つながったら送る。通信エラーと 5xx は指数バックオフでやり直し、4xx はやり直さない

### ⑥ Vision での見守り ＋ Jev での判断

- 端末内の Vision で、手の動き（フレーム差分・手の姿勢検出）と、顔が画面の前にあるかを数秒ごとに見る。映像は外に送らない
- 手が一定時間（初期値 3 分、設定で変更可）止まっていたら、規則で「今、声をかけるべきか」を判定し、必要なら「どこか考え中？ちょっと見せて？」と聞く。子どもが同意したら撮影する
- 席を立ったら（顔がない）セッションを一時停止する
- 実装（#30・`ios/HomeTeacher/Session/WatchOver/`）
  - 前のカメラ（画面側）を VGA・15fps で動かし、0.5 秒に 1 枚だけ読む。Vision で顔（`VNDetectFaceRectanglesRequest`）と手の姿勢（`VNDetectHumanHandPoseRequest`）を見て、手が映らないときのために画面の下の方の小さな濃淡の格子（32×24）のフレーム差分も使う。前のフレームについて持つのはこの格子と手の点の位置だけで、映像は送らず保存もしない
  - 手が止まった時間は、集中の時間（勉強モード）で、会話が待機中（誰も話していない）で、前に人がいるときだけ数える。設定は「見守らない / 2分 / 3分 / 5分」（初期値 3 分）。「見守らない」ならカメラも許可も使わない
  - 止まったら RuleNudgeJudge（取り組み中で、顔が前にあり、先生が 1 分以内に話していなければ声をかける）で決め、待機のままなら「どこか考え中？」「ちょっと見せて？」と聞く（判断を待つ間に話し始めたら声をかけず、あとから言い直さない）。30 秒以内の返事が「うん」「いいよ」「見て」などなら撮影する。「だいじょうぶ」などの断りや、声かけのあとでない「うん」では撮らない
  - 顔も手も動きも 30 秒続けて見えなければ「席を立った」としてタイマーを止め、1 秒続けて見えたら戻ったとしてタイマーを動かす。休憩中は止めない（休憩が終わらなくなるため）
  - 「見て」の撮影とはカメラを同時に使わない（撮る前に見守りのカメラを止め、撮ったあとで戻す）
  - 見守りのカメラが動いている間は、画面の左上に目の印（「先生が見守ってるよ」）を出す
- **Jev（TypeSafe AI Decision API）を使う場面**（#101 で公式のドキュメントと agent skill に合わせた）
  - 発話ごとに、次の 6 つを 1 回のリクエストでまとめて聞く（すべて `noul`。答えの判定の 2 つは問題に取り組み中だけ）。無音になった時点で投げ、書き起こし（空白と句読点を除く）と状況（先生が最後に話した文・問題）ごとに覚えておく
    - 先生への発話か / 言い終わったか / 撮影の依頼か / 助けを求めているか / 休憩したいか / 今日は終わりにしたいか / 問題の答えを言っているか / 正答と同じか
  - 休憩したい（0.7 以上）：集中の途中なら、その場で休憩に切り替えて雑談モードで返事する（間違えても戻せるので確かめない）。Jev が使えなければ「休憩したい」「休みたい」などの言い方で決める。「疲れた」だけでは休憩にしない（実測で迷う帯に入る）
  - 終わりたい（0.7 以上）：「今日はここまでにする？」と聞き、30 秒以内の返事が「うん」「いいよ」「終わる」などなら終える。「まだやる」「もう1問」などなら続ける。終えるとふり返りと保存が走るので、Jev の判断だけでは終えない。短い「終わり」（VoiceCommand）は今のまますぐ終える（#103）
  - 確率は 0.7 以上を「はい」、0.3 以下を「いいえ」、あいだを「決まらない」として、判定ごとに決め方を書く。Jev の失敗は「いいえ」として扱わない
  - 質問文は英語にし、発話は日本語のまま送る（Jev の主な学習言語は英語。2026-11-03 の実測で撮影の依頼の判定が 7 問中 4 → 7 正解になった）。モデルは `jev-1.14.0` に固定する（しきい値を調整しているため）
  - 「今、声をかけるべきか」は聞かない（材料が数と段階だけで、Jev は数の比較が苦手。「〜すべきか」の決定を聞くのも勧められていない）
  - 意図の `choice`（質問 / 答え / 雑談 / 休憩したい / 終わりたい / その他）と正しそうかの `score` はやめた（同時に当てはまる意図を 1 つに選ばせることになり、「その他」は「当てはまらない」の扱いが弱い。正しそうかの真ん中の段に 2 つの意味が入っていた）
  - 実測（架空の発話 23 件）: 6 問まとめて p50 約 170ms・p90 約 220ms
- Jev が使えないときは、規則ベースで代わりに判定する（先生への発話は応える側、撮影の依頼と助けを求めているかは言い方、言い終わったかは無音、答えは数の照合）

## 4. Claude の使い分け

| 役割 | モデル | 理由 |
| --- | --- | --- |
| 会話の受け答え・相づち・声かけ・雑談 | `claude-haiku-5-5` | 速さが体験を決める |
| 問題の分析・ヒントの組み立て・Generative UI | `claude-sonnet-5-5` | 画像の読み取りと構造化の質 |
| （今後）難問・作文の講評 | `claude-opus-5-5` | 今回は使わない。待ち時間と費用を優先し、Sonnet で足りない場面が実際に出たら検討する（#64） |
| 速い Yes/No・分類 | Jev | 安く速い |

- Haiku と Sonnet は同じ会話履歴を共有する。Sonnet の分析結果（問題の種類・正答・ヒントの段階）は「先生のメモ」としてシステムプロンプトに入れ、Haiku がそれに沿って話す
- プロンプトはリポジトリの `prompts/` で管理する（キャラクター設定・ヒントの段階・安全ルール・部品カタログ）
- **キャラごとの性格**（#117, #119）：一覧は `prompts/characters/characters.json`、性格は `prompts/characters/<id>.md`。`teacher.md` は役目・話し方のきまり・気持ちのしるし・教え方の共通部分で、`{{character_profile}}` に性格が入る。`hint_ladder` と `safety` は全キャラ共通。キャラの部分はキャッシュする前半（先生のメモより前）に入る
- 会話（Haiku）はプロンプトキャッシュを使う（#97）。system を先生のメモの手前で2つの block に分け、前の block とリクエストの最上位（自動キャッシュ。会話の履歴）に `cache_control` を付ける。ツール ＋ system（約1.06万トークン）は2ターン目から読み込み（入力の約1割の単価）になり、先生のメモが変わってもメモから後ろだけを書き直す

## 6. 確認方法（検証）

| 種類 | 対象 | 方法 |
| --- | --- | --- |
| 自動テスト | プロンプトの組み立て、ヒント段階の状態遷移、部品 JSON のデコード、口パクの母音変換、Worker の API | `xcodebuild test`、`vitest` |
| シミュレーター | 画面、BoardView、アバターの状態遷移、ダッシュボード | AI が iOS Simulator とブラウザでスクリーンショットを撮って確認 |
| 実機（ユーザー） | マイク・聞き取り・割り込み・エコー・カメラ・Vision | `実機確認` ラベルの issue にチェックリストを書き、ユーザーが iPad で確認する |

- 初日の実機確認は最大のリスクから：① SpeechAnalyzer で日本語が使えるか、② voice processing でエコーが十分に消えるか（割り込みが成立するか）
  - 2026-11-03 の結果（iPad Air 13-inch M2 / iOS 27.0.1、#9 の自動検証）：SpeechTranscriber は ja-JP に対応し端末内モデルも導入済み。voice processing ON で先生の声の混入率 0%、OFF で 34%。voice processing は必須。再生中の子どもの声が通るか（割り込み）は未確認
  - 実機では AVSpeechSynthesizer の終端バッファや AVAudioPlayerNode の再生完了コールバックが来ないことがあるため、待つ処理には必ずタイムアウトを入れる

## 7. リスクと対策

| リスク | 対策 |
| --- | --- |
| SpeechAnalyzer が日本語非対応 | 実機で対応を確認済み（#9）。念のため SFSpeechRecognizer（端末内モード）へのフォールバックは残す |
| エコーで割り込みが誤作動する | 割り込みのしきい値を上げる → だめなら「話している間はマイクを止める」方式 |
| 応答が遅く会話が不自然 | 文単位で TTS、定型句キャッシュ、相づち、Haiku の先行応答 |
| Claude が答えを言ってしまう | 正答は「先生のメモ」に隠し、出力を Jev / 規則で検査してから話す |
| 実機確認の時間が足りない | シミュレーターで確認できる部分を先に固め、実機確認はチェックリスト化 |
